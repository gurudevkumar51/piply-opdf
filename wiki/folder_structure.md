# Piply OPDF Folder Structure

## Project root

```text
piply-opdf/
  app/
  config/
  dataset/
  docs/
  piply_opdf/
  tests/
  uploads/
  README.md
  pyproject.toml
  context.md
  idea.md
  grid-detector.md
  technical_architecture.md
  status.md
```

## Key folders

### `piply_opdf/`

Main Python package.

- `document.py`
  - high-level orchestration API
- `cli.py`
  - Typer CLI entrypoint
- `config.py`
  - config loading and merge logic
- `phases/`
  - assessment and enhancement phase implementations
- `detectors/`
  - high-level structure detectors
- `layout/`
  - table/grid processing internals
- `models/`
  - Pydantic contracts
- `utils/`
  - helper utilities

### `app/`

FastAPI-based review and processing application.

- `main.py`
  - API routes and page serving
- `services.py`
  - background pipeline execution and DB population
- `ocr_service.py`
  - knowledge lookup + PaddleOCR + Tesseract fallback flow
- `models.py`
  - SQLAlchemy tables
- `templates/`
  - HTML UI
- `static/`
  - frontend assets

### `config/`

- `default.yaml`
  - project-wide defaults for thresholds, OCR, layout, and logging

### `tests/`

- `tests/unit/`
  - primary unit tests
- project root also contains several ad hoc script-style test files for manual experimentation

### `docs/`

Existing project docs. Some are legacy or optimistic relative to the current codebase, so they should be read with that in mind.

## Output folders created at runtime

### `<document>_piply/`

Generated by the package processing flow.

Expected contents:

```text
<document>_piply/
  assessment.json
  <document>_enhanced.pdf
  layouts/
  debug/
  pages/
  pages_enhanced/
```

### `uploads/`

Input files uploaded through the FastAPI app.

## Notes

- There are signs of an ongoing refactor from older phase-oriented modules to detector- and metadata-oriented modules.
- Some detector folders are present mainly as structure placeholders while implementation detail currently lives elsewhere.
